# BPMN 节点属性表（导出 / 导入）— 设计

## 意图（为什么做）

用户从源系统导出的 BPMN 信息不全，需要手工补全节点信息（不限于“负责人”“信息系统”，属性种类由用户自己定）。补全后的信息要能在已有的查看器里按属性筛选、高亮（见 `2026-10-19-bpmn-viewer-design.md`）。

手工往 XML 里写属性不现实（合并后的流程最多约 1000 个节点），所以要做一个**用表格来回编辑属性**的工具：

1. 从 BPMN 导出一张表：每个节点一行，已有属性各占一列；
2. 用户在 Excel 里补全、修改，或新加一列来定义新属性；
3. 把表导回，程序按节点名称把每行写成对应节点的属性，并给出报告。

属性的存放格式沿用查看器设计中已经约定的 `b2g:properties / b2g:property` 结构，查看器无需改动就能筛选新属性。

## 用户已确认

- 表格格式：**Excel（.xlsx）或 CSV**。**第一列是节点名称，后续每一列是一个属性，列标题就是属性名**。属性名不写死，完全由表头决定。
- **按节点名称匹配**。
- 既能写进**合并前的原 BPMN 文件**，也能写进**合并后的 BPMN 文件**。
- 要能**从 BPMN 导出表格**：列出全部节点名称，节点已有的属性也一并导出；用户在表里修改、新增属性列后再导回。
- **以表格为准**：表里某个格子清空、或整列删掉，导回时节点上原来的这个属性也要删掉。
- 导回时**直接修改所选的 BPMN 文件**（不另存）。
- 要有**图形界面入口**，要有**报告**。
- 目前还没有真实的表，开发时用 `tests/fixtures/` 的三个 BPMN 导出一份，补上假数据作为测试样例。

## 目标 / 非目标 / 反目标

- 目标：
  - 导出：选一个或多个 BPMN → 生成 .xlsx 或 .csv 属性表。
  - 导入：选同样的 BPMN 和填好的表 → 直接改写这些 BPMN 的节点属性，生成报告。
  - 导出 → 不做任何修改 → 导入，BPMN 的属性不发生任何变化（来回一致）。
  - 导入后的文件能被查看器正常打开，新属性出现在筛选列表中。
- 非目标（本期不做）：
  - 按 ID 或“文件 + 名称”匹配（以后可能加，本期只按名称）；
  - 老格式 .xls；一个工作簿中的多个工作表（只读第一个工作表）；
  - 在程序里直接编辑表格（编辑在 Excel / WPS 中完成）；
  - 连线的属性。
- 反目标（技术上能跑也算失败）：
  - 导回时丢失或改坏 BPMN 中与属性无关的内容（泳池、泳道、消息流、注释、布局、其它扩展元素等）。现有的 BPMN 读写流程会忽略这些元素，**不能拿来做导回**。
  - 表格读到一半出错，结果有的文件改了、有的没改。
  - 中文在 Excel / WPS 中打开是乱码，或者用 Excel 另存的 CSV 读不进来。
  - 需要安装第三方 Python 包（项目只用标准库，这一点保持）。

## 方案

### 哪些元素算“节点”

`FLOW_NODE_TYPES` 中的 BPMN 元素（任务、事件、网关、子流程等），**位于文件中任意层级**（包括非空子流程内部的节点），与查看器的判定一致。名称为空（去掉首尾空格后为空）的节点不进表，也不会被修改。

名称比较方式：去掉首尾空白后完全相同（与合并规则一致）。

### 表格结构

| 节点名称 | 所在文件 | 元素类型 | 来源流程 | 负责人 | 信息系统 | …… |
|---|---|---|---|---|---|---|
| 部门领导审核 | 科技创新平台策划；科技创新平台申报 | 人工任务 | …… | 部门领导 | OA；科研管理系统 | |

- **第一列**：节点名称，每个不同的名称一行。导出时表头写“节点名称”；导入时第一列的表头叫什么都行，一律视为名称列。
- **只读参考列**（我的决定）：`所在文件`（该名称出现在哪些所选文件中，文件名不含扩展名）、`元素类型`（中文类型名，对照表与查看器 `properties.js` 中的 `TYPE_LABELS` 一致；同名节点类型不同时列出全部）、`来源流程`（合并时程序自动写入的属性，只在有此属性时导出这一列）。这三列只是方便用户填表时参考，**导入时按表头名称识别并忽略**，节点上已有的「来源流程」属性在导入时原样保留。用户删掉这几列也没关系。
- **属性列**：其余每一列是一个属性，表头即属性名（去掉首尾空格）。导出时按属性在文件中首次出现的顺序排列。
- **多值**：一个格子里的多个取值用分号分隔，中文“；”和英文“;”都认；导出时用“；”连接。导入时按分号拆开、去掉首尾空格、丢弃空值、按出现顺序去重。
- 导出只读取 `b2g:property`（我的决定）。Camunda / Zeebe 的 `properties` 不导出，导入时也不碰。
- 导出时行的顺序：按所选文件的顺序、文件内按节点在 XML 中出现的顺序（我的决定；方便与流程对照）。

### 同名节点

- 多个所选文件中的同名节点，按合并规则视为同一个节点，在表里只占一行；导入时这一行写入所有同名节点。
- 同一文件中的同名节点同样只占一行，导入时全部写入，报告中提醒。
- 导出时，如果同名节点的属性取值不一致，该行取各节点取值的并集（与合并模式的做法一致），并在导出摘要中列出这些名称，提醒用户：导回后它们会被统一成表中的取值。
- **会被展开的空子流程**（我的决定）：合并时，一个空的 `subProcess` / `callActivity`，如果它的名称等于另一个所选文件的文件名或 process 名称，就不按名称合并，而是并入那个文件的第一个开始事件，合并后的节点使用开始事件的名称（见 `merger.py` 第 1 步“空子流程展开”）。属性表沿用同一规则：当调用方文件和目标文件**都在所选列表中**时，这个空子流程不单独占一行，而是归到目标文件第一个开始事件的那一行；导入时，这一行的属性也写进这个空子流程。这样，从原文件导出的表和从合并后文件导出的表行行对得上，合并后也不会因为两行填了不同的值而把单值属性变成多值。判定规则与 `merger.py` 保持一致（最好抽出共用函数）；导出摘要和导入报告中列出每个这样归并的子流程。目标文件不在所选列表中时，空子流程按普通节点处理，单独占一行。

### 导入规则（以表格为准）

对表中每一个能匹配到节点的行，导入后该节点的 b2g 属性 = 「来源流程」原值 + 表中这一行各属性列的取值：

- 格子有值 → 写入（覆盖原值）；
- 格子为空 → 删除该属性；
- 表中没有的属性列（被删掉的列）→ 删除该属性；
- 新增的列 → 成为新属性。

**表中没有的节点**（我的决定，用户已过目）：完全不动，并在报告中列出。“漏一行”更可能是误操作，而不是想清空它的全部属性。

### 什么情况整个导入中止（一个文件都不写）

先读表、校验、在内存中算出所有文件的新内容，全部成功后才开始写文件。以下情况中止，并在报告中说明原因（我的决定）：

- 表格无法读取（格式错误、文件被占用等）；
- 表中没有数据行（只有表头或全空）；
- 表中**一个属性列都没有**（除名称列和只读参考列外没有其它列）。按“以表格为准”，这种表会把所有节点的属性一次清空，几乎可以肯定是误操作；真想清空，可以保留表头、把格子清空；
- 属性列表头为空，但这一列下面有数据；
- 某一行名称为空，但属性格子里有数据（名称很可能被误删，跳过会让填好的数据悄悄丢失）。名称和属性都为空的行直接跳过；
- 两列表头相同（去掉首尾空格后）；
- 同一个节点名称在表中出现了不止一行（无法判断以哪一行为准）；
- 某个 BPMN 文件无法解析。

名称在 BPMN 里找不到的行**不**中止，只在报告中列出。

### 写回 BPMN 文件

- **直接在原文件的 XML 上修改**，不经过现有的读 BPMN → 内部模型 → 写 BPMN 流程。只改动匹配到的节点下的 `b2g:properties`：删掉旧的 `b2g:properties`，按需写入新的；`extensionElements` 中的其它内容保持不变；节点没有 `extensionElements` 时新建一个，位置放在 `documentation` 之后、其它子元素之前（BPMN 规范要求的顺序，`properties.with_b2g_properties` 已经这样做）；`extensionElements` 变空时删掉它。
- 文件中其它内容在语义上必须保持不变：保留原有的命名空间前缀（按文件中声明的前缀注册后再序列化，`b2g` 前缀沿用已有约定）、保留 XML 注释、保留所有不认识的元素和属性。排版（缩进、换行）可以变化。
- 只写真正有变化的文件；没有变化的文件不碰，也不生成备份。
- **备份**（我的决定）：写之前把原文件复制为同目录下的 `原文件名.bpmn.bak`。每次导入都会覆盖上一次的备份，即备份始终是“本次导入之前”的状态。
- 写入时先写临时文件再替换原文件，避免写到一半中断留下坏文件。

### 表格读写（只用标准库）

- **.xlsx 写出**：用 `zipfile` 生成一个最小的工作簿（单个工作表，名为“属性”）。首行加粗并冻结；只读参考列用浅灰底色区分；列宽按内容大致设定。全部单元格写为文本。
- **.xlsx 读取**：读第一个工作表。需要支持共享字符串、内联字符串、数字、布尔值，以及 Excel 和 **WPS** 保存的文件（用户在国内，WPS 很常见）。数字转成文本的规则（我的决定）：
  - 整数值的浮点数去掉 `.0`；
  - **日期**：单元格的数字格式是日期格式时（内置格式号 14–22，或自定义格式中含 y/m/d 日期占位符且不是纯时间格式），转成 `YYYY-MM-DD`（有时间部分则加 ` HH:MM`）。这需要读 `styles.xml` 中的 `cellXfs` 和 `numFmts`；
  - 其它数字（百分比、科学计数法等）按原始存储值输出，不还原显示格式。这是已知限制，写进 README：需要原样保存的内容（编号、百分比），请在 Excel 中把单元格设为“文本”格式后再填。导出的 xlsx 本来就全部是文本单元格，已有的值来回不会变。
- **CSV 写出**：UTF-8 带 BOM，Excel 直接打开中文不乱码。
- **CSV 读取**：先按 UTF-8（含 BOM）读，失败则按 GBK 读（中文 Windows 上 Excel 另存 CSV 默认是 GBK）。分隔符为逗号。
- **默认用 .xlsx**（我的决定）：图形界面的保存对话框和命令行文档都以 .xlsx 为默认。CSV 在 Excel 中打开再保存时，“001”会变成“1”、“1-2”会变成日期，导出 → 不改 → 导入就不再一致。这是 Excel 的行为，程序防不住，作为已知限制写进 README，并在导出 CSV 时于结果区提示一次。
- 表格文件在 Excel 中打开时，写出会因文件被占用而失败；此时给出明确提示“请先在 Excel 中关闭该文件”，而不是抛出原始异常。

### 报告

导入完成（或中止）后生成报告，在图形界面结果区显示，同时写到表格旁边的 `表格文件名.import-report.txt`（UTF-8）。内容：

1. 结论：成功 / 中止（及原因）；
2. 修改了哪些文件、各更新了多少个节点；备份文件位置；
3. 表中找不到对应节点的名称；
4. 表中没有的节点名称（未改动）；
5. 同一文件中同名、被一并写入的节点；
6. 每个有变化的节点名称：新增、修改、删除了哪些属性（修改写出旧值 → 新值）；
7. 被忽略的只读参考列。

导出也给出一段简短摘要（导出了多少行、多少个属性列、同名节点取值不一致的名称），显示在结果区，不写文件。

### 入口

- **命令行**（我的决定，与现有命令风格一致）：
  - `python -m bpmn2graphml props-export a.bpmn b.bpmn -o 属性表.xlsx`（按 `-o` 的扩展名决定 .xlsx 或 .csv）
  - `python -m bpmn2graphml props-import 属性表.xlsx a.bpmn b.bpmn`
- **图形界面**：在现有窗口中新增页签“属性表”：
  - BPMN 文件列表（添加 / 移除，与“BPMN → GraphML”页签的列表用法相同）；
  - 「导出表格…」按钮：弹出保存对话框，可选 .xlsx 或 .csv；
  - 「导入表格…」按钮：弹出打开对话框，选择表格后直接写入列表中的 BPMN 文件；
  - 结果区显示导出摘要或导入报告；
  - 「在查看器中打开」按钮：打开列表中选中的文件（未选中时打开第一个）。
- README 增加“属性表”一节。

### 文件位置（建议）

```
bpmn2graphml/
  table_io.py        # .xlsx / .csv 读写（纯表格，不涉及 BPMN）
  prop_table.py      # 导出表格、导入表格、就地改写 BPMN、生成报告
tests/
  test_table_io.py
  test_prop_table.py
```

## 留给实现者的部分

- 模块内部的函数划分；xlsx 的具体样式细节。
- 就地改写时保留命名空间前缀和注释的具体做法（例如 `ET.XMLParser(target=ET.TreeBuilder(insert_comments=True))` 加按文件声明注册前缀），只要满足上面“语义不变”的要求。
- 元素类型中文名对照表在 Python 中的放置位置（可与 `properties.py` 放在一起）。

## 我做的决定（请过目）

- 导出表中带三个只读参考列：所在文件、元素类型、来源流程；导入时按表头名称识别并忽略。
- 多值用分号分隔（中英文分号都认），导出用“；”。
- 表中没有的节点完全不动，只在报告中列出。
- 同一名称在表中出现多行、表头重复、空表头有数据时，整个导入中止。
- 导出时同名节点取值不一致取并集，并在摘要中提醒。
- 只读写 `b2g:property`，不碰 Camunda / Zeebe 的属性。
- 就地改写只替换 `b2g:properties`，不经过现有的读写流程；改写前生成 `.bak` 备份，每次覆盖。
- 只支持 .xlsx（不支持 .xls），只读第一个工作表；CSV 读取兼容 UTF-8 与 GBK。
- 包括非空子流程内部的节点。
- 会被展开的空子流程归到目标文件开始事件的那一行（与合并规则一致）。
- 表中一个属性列都没有、或名称为空的行有数据时，中止导入。
- xlsx 中的日期单元格转成 `YYYY-MM-DD`，其它数字按存储值；默认导出 .xlsx，CSV 被 Excel 改写数值作为已知限制。
- 命令行新增 `props-export` / `props-import`；图形界面新增“属性表”页签。

## 验证

- `table_io`：
  - xlsx 写出后能读回相同内容（含中文、空格子、多值、数字）；
  - 能读取用 Excel 保存的 xlsx 样例（共享字符串、数字单元格）——测试样例由实现者用最小 XML 手工构造，覆盖共享字符串、内联字符串、数字、空行、稀疏单元格（中间有空列的行）；
  - CSV：UTF-8 带 BOM 与 GBK 两种编码都能读。
- `prop_table`：
  - 用三个 fixture 导出 → 原样导入：BPMN 属性无变化，没有文件被改写；
  - 填值、清空格子、删列、加列四种操作的结果符合导入规则；
  - 「来源流程」在导入后保留；
  - 多个文件中的同名节点都被写入；
  - 中止条件（重复行、重复表头、空表头有数据、没有属性列、名称为空的行有数据）下没有任何文件被改写；
  - 三个 fixture 一起导出时，「科技创新平台申报」空子流程归入「启动平台申报」那一行；导入后两者属性相同；只选策划.bpmn 时它单独占一行；
  - xlsx 日期格式单元格读成 `YYYY-MM-DD`；
  - 改写后的文件：除 `b2g:properties` 外，与改写前的 XML 在语义上相同（逐元素比较标签、属性、文本），命名空间前缀不变；能被 `read_bpmn` 正常读取；
  - 报告包含上面列出的各部分。
- 端到端：导入后用查看器打开文件，新属性出现在筛选下拉框中，计数正确。
