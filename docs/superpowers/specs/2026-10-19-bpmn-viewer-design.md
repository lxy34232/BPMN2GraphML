# BPMN 属性筛选可视化查看器 — 设计

## 意图（为什么做）

转换器已经可以把多个 BPMN 合并成一个流程（见 `2026-10-19-bpmn-yed-merge-design.md`）。用户下一步想**在网页中浏览一个 BPMN 流程，并按节点的属性信息做可视化检查**：选一个属性和它的若干取值，图中匹配的节点高亮，其余节点变淡。

第一个用例是“来源流程”：在合并后的流程里，看出每个原流程分别包含哪些节点。但用户真正想要的是一种通用能力。以后他会另做一个工具，用类似配置表的方式往 BPMN 节点上补充“负责人”“使用的信息系统”等属性，再在这个查看器里查看、筛选、交互这些信息。所以查看器**不能把属性名写死**：新属性出现在文件里，就应该自动出现在筛选列表中。

## 用户已确认

- 打开的是 **BPMN 文件**，合并前的单个流程或合并后的流程都可以。
- **不再考虑导回原企业平台**：合并输出可以无条件写入新的扩展属性。
- **一次只看一个流程**，不需要多流程对比。
- 核心交互：**按节点属性筛选并高亮**。“来源流程”只是其中一个属性；以后配置表补充的属性也要能用同样的方式筛选。
- 页面布局用 **B 方案**：顶部工具条（打开文件 + 属性下拉框 + 一排可点的取值标签，标签上带节点数），流程图占满页面，点击节点后在旁边弹出浮动详情卡。

## 目标 / 非目标 / 反目标

- 目标：
  - 本地打开一个 BPMN 文件，正确渲染流程图，可以缩放和拖动。
  - 选属性 → 选一个或多个取值 → 高亮匹配节点、淡化其余节点。
  - 点击节点，查看它的全部属性。
  - 文件中出现的任意自定义属性都能被自动发现并用于筛选。
- 非目标（本期不做）：
  - 编辑 BPMN；
  - 配置表工具本身（以后单独做，但本期要定好它写入的属性格式）；
  - 多流程对比；
  - 按名称搜索节点；
  - 导出图片；
  - 对连线做属性筛选；
  - 泳道等元素。
- 反目标（技术上能跑也算失败）：
  - 需要联网才能使用。用户在国内，CDN 访问不稳定，所有依赖必须随项目放在本地。
  - 属性名写死在代码里，新增属性后要改代码才能筛选。
  - 打开合并前的普通 BPMN（没有任何自定义属性）时报错或显示空白。

## 方案

### 技术选型（我的决定）

- **渲染库：bpmn-js 17.11.1 的 `NavigatedViewer`**。这是 bpmn.io 的官方查看器，自带缩放和拖动。它提供 `canvas.addMarker(id, cssClass)`，可以给元素加或去掉 CSS 类来实现高亮和淡化，`element.click` 事件用于点击查看详情。本项目阶段一已经用它验证过输出的渲染效果。
  - 没有选 bpmn-visualization：它的高亮能力同样合适，但对标签等细节的渲染不如 bpmn-js 完整，而且项目已经验证过 bpmn-js。
  - 没有选 react-bpmn：只是包了一层 React，会引入构建工具链。
  - 没有选 bpmn-python：它是 Python 的解析和绘图库，不适合用来做网页前端。
- **纯静态页面，不需要构建，也不需要服务器**：原生 HTML + CSS + JavaScript（经典 `<script>`，不使用 ES module，因为浏览器从 `file://` 打开页面时会拦截 module 脚本）。直接双击 `index.html` 就能打开。
- **依赖放在本地**：把 bpmn-js 发布包中的 `bpmn-navigated-viewer.production.min.js` 和它的 CSS、字体文件下载后提交到仓库的 `vendor/` 目录，同时附上 bpmn-js 的 LICENSE。按 bpmn.io 许可证的要求，保留图上的 bpmn.io 水印。
- **读取属性不依赖 bpmn-js 的内部模型**：用浏览器的 `DOMParser` 直接解析 BPMN XML，按命名空间无关的方式提取每个节点的属性；bpmn-js 只负责渲染。

### 属性的存放格式（约定，以后的配置表工具也写这个格式）

属性写在节点的 `extensionElements` 中。命名空间 URI 为 `https://github.com/lxy34232/BPMN2GraphML/properties`，前缀 `b2g`：

```xml
<bpmn2:manualTask id="..." name="部门领导审核">
  <bpmn2:extensionElements>
    <b2g:properties>
      <b2g:property name="来源流程" value="科技创新平台策划"/>
      <b2g:property name="来源流程" value="科技创新平台申报"/>
      <b2g:property name="负责人" value="部门领导"/>
    </b2g:properties>
  </bpmn2:extensionElements>
  ...
</bpmn2:manualTask>
```

- 一个属性有多个取值时，就重复写同名的 `property`。
- 只认这一种结构。普通的 XML 自定义属性（例如 `ext:owner="..."`）和其它扩展元素不当作可筛选属性（我的决定）：格式单一，配置表工具和查看器才能对得上；需要的话，以后再加映射。
- 查看器读取时**兼容同结构的常见写法**：`extensionElements` 下任何本地名为 `properties` 的元素，只要它的子元素本地名为 `property`、并带有 `name` 和 `value` 属性，都会被读取。例如 Camunda 的 `camunda:properties` 和 Zeebe 的 `zeebe:properties`。

### 查看器中的属性来源

1. **内置属性「元素类型」**：由 BPMN 元素类型得出，用中文显示（人工任务、用户任务、排他网关、开始事件……），未知类型显示原标签名。这样合并前的普通 BPMN 也至少有一个属性可以筛选。
2. **扩展属性**：按上面的格式读取。属性名就是筛选下拉框里的选项，按在文件中首次出现的顺序排列，“元素类型”固定排在最前面。

只有流程节点（任务、事件、网关、子流程等）参与筛选；连线和根元素不参与。

**缺少属性的节点**（我的决定）：选中某个属性后，所有没有该属性的节点归入一个特殊标签「（未设置）」，它和普通取值一样带计数、可以选中。这样能直接查出“哪些节点还没填负责人”，正好用来检查配置表补得全不全；在 yEd 中新增、因而没有来源的节点，也会落在「来源流程 →（未设置）」里。

### 转换器侧的配合（Python）

- **合并模式**输出 BPMN 时，给每个节点写入「来源流程」属性，取值为该节点所有 origin 的文件名（去重，保持顺序）。
  - 被展开的子流程并入了目标流程的开始事件，所以这个节点的来源也包括调用方文件（例如同时属于“策划”和“申报”）。这是有意为之：它正是两个流程的接合点。
  - 如果节点原本已有 `extensionElements`，就并入其中。
  - 如果已有名为「来源流程」的 `b2g:property`（例如对已合并的文件再次合并），先删掉旧的再写入，避免重复。
- **合并模式合并所有 origin 的 `b2g` 属性**（我的决定）：配置表工具以后可能往合并前的原文件里写属性。同名节点合并时，把各 origin 的 `b2g:property` 按（名称, 取值）去重后全部保留为多值，不做“首个优先”。其它扩展内容仍按现状，取首个 origin 的。
- **拆分模式**保持不变，原文件内容不做任何改动。
- 命名空间前缀 `b2g` 加入 `bpmn_writer` 的固定前缀表。
- 命令行新增 `python -m bpmn2graphml view [BPMN文件]`，用系统默认浏览器打开查看器。图形界面也新增对应按钮：「GraphML → BPMN」页签在转换完成后可以「在查看器中打开」合并结果；另有一个不带文件的「打开可视化查看器」按钮。
  - 带文件打开时（我的决定）：浏览器从 `file://` 打开的页面不能读取任意本地路径，所以由 Python 在系统临时目录生成一个启动页。这个页面以绝对 `file://` 地址引用查看器的脚本和样式，把 BPMN 内容嵌在 `<script type="text/plain">` 中，页面加载后自动打开。不需要服务器。

### 页面行为（B 方案）

- **顶部工具条**：
  - 「打开 BPMN」按钮（文件选择框）。也支持把文件拖进页面。
  - 当前文件名。
  - 「属性」下拉框。
  - 一排取值标签，每个标签显示“取值 + 节点数”，点击切换选中，可以多选。
  - 「清除筛选」按钮、「适应窗口」按钮。
- **高亮规则**：
  - 没有选中任何取值时，不做任何高亮或淡化。
  - 选中后，节点的该属性有任意一个取值被选中（多选之间为“或”的关系），就高亮：橙色描边加浅橙底色。其余节点淡化，半透明。
  - 连线：两端都高亮的连线保持正常显示，其余连线淡化。
  - 切换属性时清空已选的取值。
- **详情卡**：
  - 点击节点，在节点旁浮出卡片，显示名称、元素类型、ID，以及全部扩展属性。同名多值用“、”连接。
  - 点击画布空白处或按 Esc 关闭。
- **空状态**：没有打开文件时，页面中央显示“打开或拖入一个 BPMN 文件”。文件无法解析时，在页面上显示带文件名的错误信息，不弹浏览器原生对话框。
- **没有布局信息（BPMNDI）的文件**（我的决定）：bpmn-js 无法画出这种文件，页面上明确提示“该文件没有图形布局信息（BPMNDI），无法显示流程图；可先经 yEd 布局并用本工具转回 BPMN 后再查看”，不显示空白画布。本期不内置自动布局库：用户的真实文件都带布局，没有布局的文件可以走 yEd 流程补上。
- 界面文字为中文。

### 文件位置

```
bpmn2graphml/viewer/
  index.html
  app.css
  app.js            # 页面逻辑：加载文件、驱动 bpmn-js、筛选交互、详情卡
  properties.js     # 纯逻辑：从解析后的 XML 提取节点属性、建立属性索引、计算匹配；不依赖 DOM 渲染，可在 Node 中测试
  vendor/bpmn-js/   # bpmn-navigated-viewer.production.min.js、assets/*.css、字体、LICENSE
tests/viewer/        # Node 内置 test runner（node --test）测试 properties.js
```

查看器放在 Python 包目录内，是为了让 `view` 命令能通过 `__file__` 找到它；`pyproject.toml` 需要把 `viewer/**` 声明为 package data。

## 我做的决定（请过目）

- 渲染库用 bpmn-js 的 NavigatedViewer；纯静态页面，依赖放在本地，可以离线使用。
- 属性只认 `properties/property` 这一种结构，包括 b2g、Camunda、Zeebe 的写法；普通 XML 属性不算可筛选属性。
- 内置一个「元素类型」属性；缺少所选属性的节点归入「（未设置）」标签。
- 合并时把各原文件节点上的 b2g 属性全部保留为多值。
- 被展开的子流程入口节点同时属于调用方和目标流程。
- `view` 命令带文件打开时，由 Python 生成临时启动页。
- 没有布局信息的文件只给出提示，不做自动布局。
- 连线不参与筛选；两端都高亮的连线保持正常显示，其余淡化。

## 验证

- Python：
  - 合并模式输出中每个节点都有正确的「来源流程」属性；
  - 原有的 `extensionElements` 内容保留；
  - 重复合并不会产生重复属性；
  - 同名节点合并时，各 origin 的 b2g 属性都保留；
  - 拆分模式输出与改动前完全一致（现有测试继续通过）；
  - `view` 命令生成的启动页嵌入了正确的 BPMN 内容。
- JavaScript：用 `node --test` 测试 `properties.js`，覆盖：属性提取（b2g / camunda 写法、多值、无属性节点）、索引计数、多选匹配。
- 端到端：用 Playwright 打开查看器，分别载入合并后的 BPMN 和一个合并前的 BPMN。检查：
  - 渲染无警告；
  - 下拉框里有「元素类型」和「来源流程」；
  - 选中某个来源流程后，高亮的节点数与标签上的计数一致；
  - 点击节点能弹出详情卡；
  - 断网状态下（不访问任何外部 URL）也能正常工作。
